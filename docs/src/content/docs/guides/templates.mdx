`Vitreous.Templates` is a `dotnet new` template pack. A template gives you a project that builds, runs and passes its tests on the first try, with the handlers, behaviors and HTTP mapping already wired up the way the rest of these docs describe.

```sh
dotnet new install Vitreous.Templates
dotnet new vitreous-api -n Shop
cd Shop
dotnet run --project src/Shop
```

Each generated project has a `README.md` that explains its layout, how to run and test it, and where the next feature goes.

## `vitreous-api`

An ASP.NET Core minimal API organized in **vertical slices**: each feature keeps its command or query, validator, handler and endpoint in one file, so you read, change or delete a feature in one place.

```text
Shop/
  Shop.slnx                   Shop.sln with -f net8.0
  Directory.Build.props       target framework, nullable, warnings as errors
  Directory.Packages.props    every package version, in one place
  src/Shop/
    Program.cs                registration: handlers, behaviors, validation, caching, DevUI
    Common/
      ResultHttpExtensions.cs ToHttpResult(): Error.Code → status code
      LoggingBehavior.cs      an open-generic pipeline behavior
    Features/Todos/
      CreateTodo.cs           command + validator + handler + endpoint
      GetTodo.cs              query
      ListTodos.cs            stream query
      CompleteTodo.cs         command without a result, publishes TodoCompleted
      TodoCompleted.cs        notification and its handler
      TodoStore.cs            in-memory storage
  tests/Shop.Tests/           endpoint tests (WebApplicationFactory) and handler tests
```

The todos are kept in memory, so the project runs with no setup. Handlers return failures as an `Error`, and `ToHttpResult()` turns them into Problem Details responses. A validation failure becomes a 400 with the messages per property, as described in [Validation](/Vitreous/guides/validation/) and [HTTP error mapping](/Vitreous/guides/http-error-mapping/). In Development, the app serves the OpenAPI document at `/openapi/v1.json`, the Scalar API reference at `/scalar/v1` and the [developer UI](/Vitreous/guides/developer-ui/) at `/vitreous`.

## Options

| Option | Values | Default | What it does |
|---|---|---|---|
| `-f`, `--framework` | `net8.0` `net9.0` `net10.0` `net11.0` | `net10.0` | The target framework. Package versions follow it, e.g. `Microsoft.AspNetCore.OpenApi` 9.x on `net9.0`. On `net8.0`, which predates `AddOpenApi()`, Swashbuckle generates the OpenAPI document, and the solution is a `.sln` because the .NET 8 SDK can't read `.slnx`. |
| `--validation` | `true` `false` | `true` | Adds `Vitreous.FluentValidation` and a validator for `CreateTodoCommand`. |
| `--devui` | `true` `false` | `true` | Adds `Vitreous.DevUI`, which is on in Development only. |
| `--caching` | `none` `memory` `redis` | `none` | `GetTodoQuery` becomes an `ICacheableQuery`, and `CompleteTodoCommand` evicts it. `memory` uses the in-memory `IDistributedCache`. `redis` uses `Vitreous.Caching.Redis`, reads the `Redis` connection string, and adds a `compose.yaml` that runs Redis locally. See [Caching](/Vitreous/guides/caching/). |
| `--tests` | `true` `false` | `true` | Adds the xUnit test project. |
| `--aot` | `true` `false` | `false` | Publishes with Native AOT: `CreateSlimBuilder`, `PublishAot` and a source-generated `JsonSerializerContext` for every type an endpoint reads or writes. See [Native AOT](/Vitreous/guides/native-aot/). |
| `--vitreous-version` | a version | the template pack's own | The version of the Vitreous packages to reference. |
| `--no-restore` | | | Skips the restore after the project is created. |

<Aside type="note">
`--aot` turns `--validation` and `--devui` off: FluentValidation and the developer UI aren't AOT-compatible. Without validation, `CreateTodoHandler` checks the title itself and returns `Error.Validation`.
</Aside>

```sh
dotnet new vitreous-api -n Shop -f net8.0
dotnet new vitreous-api -n Shop --caching redis
dotnet new vitreous-api -n Shop --aot --caching memory
```

## Versions

A template references the Vitreous version it shipped with: `Vitreous.Templates` 0.6.0 creates projects on Vitreous 0.6.0. Update the template pack with `dotnet new update`, or pass `--vitreous-version` to create a project on another release. `Vitreous` and `Vitreous.SourceGeneration` should stay on the same version: when you upgrade, change both in `Directory.Packages.props`.
